# 样式实现规则

> 当任务要按设计稿、设计规范或项目 Token 修改样式，或修复同类组件样式不一致、控件状态跳动、图标偏移时读取。视觉层级、配色、排版和设计方向这类设计判断不在本规则范围。

## 边界

本规则负责把已经确定的视觉结果正确、稳定地写进代码。“应该长什么样”，例如层级怎么排、用什么配色和字体、间距该多大、整体风格如何，以设计稿、项目设计规范或用户的明确要求为准；都没有时沿用相邻同类页面的做法，不自行发明新的视觉方案。

## 取值来源

按以下顺序确定取值：

1. 设计稿或用户明确给出的值；
2. 项目的设计变量、主题和组件变体；
3. 相邻同类组件与页面中已经符合规范的实现。

找不到对应角色时，只为当前需要的角色补最小的变量或组件变体，不顺手建立完整的设计系统。

没有渲染证据时，只修源码能够确定的硬问题，例如任意值绕过变量、同一状态使用不同样式、`transition: all`、实例覆盖组件内部；不声称视觉已经变好。

## 布局、对齐与弹性尺寸

写布局和对齐时优先用浏览器自带的弹性规则，尽量避免用硬编码像素把元素“凑”在位置上；一旦遇到换系统字体（Windows vs macOS）、高 DPI（125%/150%）或英文变长，硬编码尺寸很容易偏移、顶出或裁切：

- **水平 / 垂直居中交给 Flex 或 Grid**：优先用 `display: flex` / `grid` 配合 `align-items: center`、`justify-content: center`、`place-items: center` 和 `gap`；不要靠写死 `height === line-height`、手工凑 `padding`/`margin`/`top` 或像素偏移来模拟居中。
- **文字与控件优先弹性尺寸，少写死宽高**：按钮、标签、标题栏和混合控件行优先由内容自然撑开，或用 `min-width`、`min-height`、`flex` 分配空间；含文字的行容器用 `min-height` 替代写死 `height`（避免换字体或高 DPI 后上下裁字）。固定 `width`/`height` 只留给图标、头像、媒体比例和明确要求等宽对齐的几何控件。
- **Flex 行内明确“谁缩、谁不缩、何时换”**：
  - 动态长文本（路径、文件名、辅助说明）加 `flex: 1; min-width: 0` 并配明确溢出策略，防止把旁边的按钮挤出容器；
  - 图标、开关、主操作按钮加 `flex-shrink: 0`，保护核心控件不被压扁；
  - 窄侧栏、卡片或固定宽弹层放不下“标题 + 多按钮”或“长文案 + 控件”时，用 `flex-wrap: wrap` 或主次分行，不靠给每个子项写死像素宽去拼总宽。
- **为字重变化与多语言留余量**：`hover`/`selected` 加粗（`font-weight` 变化）会让文字变宽，紧凑按钮和标签栏不能按默认字重卡死宽度，避免选中时顶出容器或突然截断；`<canvas>` / SVG 自绘文本按当前字体下的 `measureText()` 实测宽度决定显隐或省略，不写死固定像素阈值。

## 实现规则

- 组件使用语义变量，不借用“当前看起来一样”的其他角色的值；缺少角色时补角色，不拿边框色充当文字色。
- 相同关系使用同一个间距变量。页面负责区域排列和区域间距，组件负责自身内部 padding；父级 `gap` 和子级 `margin` 不重复制造同一段距离。
- 文字使用项目已有的文字角色，不按标签名临时指定字号；需要纵向比较的数字使用等宽数字。
- 只有溢出策略明确时才截断：路径、名称等动态长内容保留查看完整内容的入口，不靠更短的 `line-clamp` 掩盖问题；按钮、导航、Tab 等核心操作词禁止靠省略号凑合，应通过弹性宽度、换行或分行保证完整可读。
- 悬停、按下、聚焦、禁用和处理中状态由共享组件维护；状态切换不改变控件的几何尺寸，预留图标、加载指示和字重变化的宽度余量。
- 图标继承 `currentColor`，同一资源不维护多份只有颜色不同的文件；图标偏心时修 SVG 的 `viewBox` 或共享图标容器，不在每个使用位置补偏移。
- 嵌套表面的圆角、边框和阴影沿用组件变量，不在实例上各自调整。

## 常见问题与代码落点

| 问题 | 优先修改 | 不要做 |
| --- | --- | --- |
| 居中歪斜、换字体或高 DPI 后上下裁字 | 改用 Flex/Grid 对齐、`gap` 与 `min-height` | 写死 `height`/`line-height` 或凑 `margin`/`top`/`padding` 偏移 |
| 窄容器、选中加粗或英文下文字挤压溢出 | Flex 行明确 `flex: 1; min-width: 0` 与 `flex-shrink: 0`，放不下就换行或分行 | 给按钮或文本行写死像素宽、或对核心操作词强加省略号 |
| 同类组件看起来不一致 | 修共享变量、默认样式或含义稳定的变体 | 用逐个实例覆盖掩盖共享实现的不一致 |
| 内容太挤或太散 | 统一父布局 `gap` 和组件内部 padding | 同时叠加 margin、gap 和空占位 |
| 控件跳动 | 稳定尺寸，预留图标、加载或加粗位置 | 状态切换时改变 padding、边框宽度或卡死未加粗宽度 |
| 图标不齐 | 修图标资源或共享图标容器 | 为每个使用位置写不同的 `translate` |

## 验证

- 用本次受影响的真实内容与状态检查溢出和一致性，至少看改动组件的默认状态和本次涉及的交互状态。
- 涉及多语言、窄容器、固定宽弹层或跨平台高 DPI（125%/150%）时，按最宽语言与最小视口检查真实渲染和几何溢出（`scrollWidth > clientWidth`、`scrollHeight > clientHeight`、兄弟元素重叠），不只看单一语言 100% 缩放；可直接注入本 Skill 的零依赖脚本 `scripts/audit_layout.js`（或运行 `node scripts/check_layout.mjs --stress` 模拟字号膨胀压力测试）定位硬编码挤压隐患。
- 修改共享变量、组件或变体后，按使用位置确认其他语义状态仍能区分。
- 没有渲染检查时明确写“未验证实际视觉”，不把源码推断报告成视觉结论。
