# 视觉工程规则

> 当任务明确要求改变视觉层级、间距、排版、颜色、圆角、边框、阴影、图标或整体完成度时读取。数据、交互和布局结构由对应规则负责；不要因为文件中存在 CSS 就读取本文件。

## 目标

视觉工程不是增加装饰，而是让用户更快看出：当前对象、主要内容、状态、分组、可操作区域和下一步动作。每次调整都必须能指出具体元素、具体属性、项目依据和代码落点。

## 先取证再改值

按以下顺序确定正确视觉：

1. 项目明确的设计变量、主题和组件变体；
2. 当前业务中已经符合规范的同类组件和相邻页面；
3. 浏览器或截图中能够确认的真实差异；
4. 本文件提供的兜底原则。

已有项目标准时，不用本文件的示例数值覆盖它。找不到标准时，只为当前必要角色补最小 Token 或组件变体，不顺手建立完整的新设计系统。

没有渲染证据时，可以修复源码中能够确定的硬问题，例如任意值绕过 Token、同一状态使用不同样式、`transition: all` 或组件实例覆盖；不要声称已经证明“视觉更好”。除非用户或项目允许，不主动调用浏览器自动化。

## 实施顺序

严格按下面顺序处理；前一层已经解决问题时停止。

### 1. 信息层级

- 一个区域只保留一个最先被看到的内容或动作；其他信息通过字号、字重、颜色和空间逐级减弱。
- 先删除重复标题、标签、图标、边框和背景，再考虑增加强调。
- 主次差异至少由一种稳定属性表达，不同时堆叠大字号、粗体、品牌色、阴影和彩色背景。

### 2. 空间与对齐

- 使用项目间距刻度，不为单个实例创造任意值。相同关系使用相同间距，不同关系必须有可辨认的间距差。
- 组内间距小于组间间距；先用留白和对齐分组，仍无法区分时才增加分隔线或背景。
- 相邻标题、正文、控件和操作栏对齐到少量共享边线；没有内容或行为理由的偏移应删除。
- 页面区域负责排列和留白，组件负责自身内部间距。不要同时在父级 `gap` 和子级 `margin` 重复制造同一距离。

### 3. 排版

- 复用项目已有的文字角色和行高，不根据标签名临时指定字号。页面标题、区域标题、正文、辅助信息和数据值应各自保持稳定角色。
- 数字需要纵向比较时使用项目已有的等宽数字能力，或 `font-variant-numeric: tabular-nums`；普通正文不强制使用。
- 标题和短说明避免因为固定高度被截断；长正文使用可读宽度，表格和紧凑工具区不套用文章行宽。
- 只有真实溢出策略明确时才截断。名称参与识别时，必须保留可查看完整内容的现有入口，不能单纯增加更短的 `line-clamp` 掩盖问题。

### 4. 颜色与表面

- 组件使用语义 Token，不直接借用“当前看起来一样”的其他角色颜色。缺少角色时补角色，不借边框色充当文字色。
- 品牌色、高饱和色和实心背景用于主要动作、选中或需要立即识别的状态；普通标题和静态信息保持中性，避免把不可点击内容画得像链接。
- 边框表达结构、分隔或状态；阴影表达浮起和层级。同一层级默认不同时用重边框和重阴影制造双重轮廓。
- 嵌套表面的圆角沿用组件 Token。内层圆角不得在视觉上大于外层；只有真实内边距和轮廓关系需要时才微调，不机械套用固定公式。
- 渐变、模糊光晕、彩色强调边和大面积有色卡片只有项目已有稳定视觉语言或内容含义时才使用。

### 5. 控件与图标

- 交互控件至少处理默认、hover、active、disabled 和 loading 中实际存在的状态；状态变化不能改变控件几何尺寸或挤动相邻内容。
- hover 表示“可以操作”，active 表示“正在按下或当前选中”，selected 表示“持续状态”；不要用同一视觉混淆三者。
- 同一界面使用同一图标库、描边风格和尺寸层级。图标继承 `currentColor`，状态差异优先由组件样式处理，不维护多份仅颜色不同的资源。
- 图标与文字组合时按视觉重量对齐；明显偏心时优先修 SVG `viewBox`、组件内对齐或小幅光学偏移，不给每个页面分别补坐标。

## 无项目标准时的有限兜底

只有项目没有对应 Token 或既有模式时才能使用，并应收敛为组件级变量：

- 间距以 `4px` 倍数建立最小刻度，常用相邻层级避免只差 `1–2px` 而无法感知；
- 普通边框使用 `1px`，不要用更粗边框代替信息层级；
- 高频 hover/active 反馈优先改变一个属性，例如背景或透明度，不同时改变颜色、位移、阴影和边框；
- 圆角、阴影和颜色只建立当前组件实际消费的角色，不生成无人使用的完整刻度。

这些值是缺少系统时的起点，不是覆盖现有产品的统一答案。

## 常见问题与代码落点

| 可见问题 | 优先修改 | 不要做 |
| --- | --- | --- |
| 页面层级混乱 | 删除重复强调，统一文字角色和组间距 | 给每块内容增加彩色背景或卡片 |
| 同类组件看起来不一致 | 修共享 Token、默认样式或含义稳定的变体 | 在页面逐个传 `className` 覆盖 |
| 内容太挤或太散 | 统一父布局 `gap` 和组件内部 padding | 同时叠加 margin、gap 和空占位 |
| 控件跳动 | 稳定尺寸，预留图标或 loading 位置 | 在状态切换时改变 padding、边框宽度 |
| 图标不齐 | 修图标资源或共享图标容器 | 为每个使用位置写不同的 translate |
| 卡片太重 | 先删装饰，选择边框或阴影中的一个 | 继续叠加渐变、描边和大阴影 |

## 验证

- 使用真实标题、长名称、数字、错误和空状态检查层级与溢出；不要只看占位文本。
- 至少检查改动组件的默认状态和本次涉及的交互状态。
- 响应式变化只检查项目实际支持的代表性视口，不为截图编造固定断点。
- 修改共享 Token、组件或变体后搜索全部使用位置，确认没有让其他语义状态失去区分。
- 没有渲染检查时明确写“未验证实际视觉”，不要把源码推断报告成视觉结论。
