# 前端验证规则

> 前端代码改动完成前读取；只读评审不要求单独读取本文件，使用对应主题规则中的检查项即可。

验证用户能够看到和操作的结果，不把类型检查、Lint 或构建通过等同于界面正确。

## 按风险选择状态

只检查本次改动能够触及的状态：

| 风险 | 至少检查 |
| --- | --- |
| 首次获取数据 | loading → ready |
| 集合浏览 | ready、empty、filtered-empty |
| 可恢复请求 | processing → error；重试后 processing → ready 或 error |
| 长任务 | queued、processing、error、ready |
| 表单或工作流 | 初始值、修改中、提交中、成功、失败保留输入 |
| 异步确认弹窗 | 提交中保持弹窗与对象、确认按钮 loading、成功更新后关闭、失败保持并可重试 |
| 兜底数据 | 使用兜底数据、恢复真实数据 |

状态必须互斥；不要为了覆盖矩阵在同一画面叠加多个状态。

## 内容与动作

本次改动触及可见内容、动作或视觉含义时，至少验证：

- 可见信息是否承担明确职责，是否删除了重复说明和无决策价值的实现信息；
- 动作是否产生真实结果，主导动作和作用范围是否清楚；
- 图标和强调边是否具有稳定含义，常见任务是否沿用用户熟悉的模式。

## 数据与流程

- 验证选择器覆盖完整可选集合，而不是当前浏览分页。
- 验证单项操作只锁定对应对象。
- 验证筛选后的批量操作范围。
- 验证自动保存、显式保存和临时预览的真实提交边界。
- 验证异步确认不会先关闭弹窗再等待结果；处理中不能重复提交或在请求不可取消时关闭，成功后底层状态已经更新，失败时对象和确认上下文仍保留。
- 验证关闭详情或编辑器后仍回到原位置和原对象。
- 验证错误恢复不会清空用户已输入内容。

## 几何与视口

根据目标产品选择代表性宽屏、窄屏和中间宽度，不使用固定设备清单代替判断。检查：

- 首屏能否看到对象、任务和主导动作；
- 长名称、长错误和真实数据密度；
- 页面、弹窗、表格和浮层分别由哪个区域滚动；
- 弹层靠近视口四周时的碰撞与裁切；
- 内容变多或变少时是否出现大块空白、跳动或根页面水平滚动；
- 固定宽高是否仍有明确必要。

## 使用位置检查

修改共享组件、函数或样式后：

- 搜索全部使用位置；
- 选择默认方式和每种使用场景的代表页面；
- 检查没有使用本次新能力的位置是否保持原行为；
- 检查页面是否仍存在绕过共享组件的局部实现；
- 检查同一含义是否只剩一个实现来源；
- 检查是否因“沿用现有模式”继续保留已确认的错误；
- 检查替换错误共享实现后，所有相关位置是否已经修改，未修改部分是否明确报告；
- 检查被替代的组件、函数、样式类、样式和引用是否已经删除。

## 自动化

- 使用项目现有类型检查、Lint、组件测试和构建验证代码规则。
- 能稳定程序化判断的回归进入项目原生检查。

## 完成报告

只报告：

- 已验证的状态、视口、数据范围和共享实现的使用位置；
- 运行的项目检查及结果；
- 未验证项及阻断原因；
- 仍需人工判断的体验取舍。
